## Summary

Adds the Versions screen (version-history T3): a read-only view of a page's saved versions,
with newest-first list, 20-at-a-time pagination, and a Restore link that hands off to the edit
screen (T4). The diff adds:

- `src/Versions.tsx` — the screen (352 lines), wired into `Shell.tsx` at `/pages/:id/versions`.
- `src/pages-api.ts` — `fetchVersions` / `fetchVersion` with runtime shape guards for the two
  new endpoints, plus the `Version` / `VersionSummary` types.
- `src/EditPage.tsx` — a **Versions** link in the Publish box, shown only when `mayEdit`.
- `src/LivePreview.tsx` — three optional props (`heading`, `frameTitle`, `emptyNote`) so the
  screen can reuse the preview with its own labels. Defaults preserve existing behaviour.
- `src/index.css` — the screen's layout tokens, using existing `--wp-*` variables.
- `e2e/versions.spec.ts` + `e2e/support/mock-api.ts::fakeVersions` / `fakeVersion` — nine mock-API
  tests covering permission, listing, pagination, preview, time zones, XSS-as-text, keyboard
  flow, and the five failure modes.
- `e2e/flow/frame.spec.ts` — unrelated flake fix (`expect.poll` instead of a one-shot `expect`).
- Visual baselines refreshed for the edit screen (the Versions link added a new line).
- `CLAUDE.md` — documents the screen.

Everything new follows established repo patterns: `authed()` for requests, `ApiError` discrimination
by `status`, `isRecord` / `textOrNull` / `isAuthor` for response guards, `formatMoment` for times,
`useSignedIn().mayEdit` for the UI permission check (API enforces — invariant 3), and the existing
`--wp-*` colour tokens. No new npm packages, no new state library, no secrets, no
`dangerouslySetInnerHTML`, no raw `fetch`.

The three-key pattern in `Versions.tsx` (`requestKey` / `detailKey` for the page+list / detail
fetches) is unusual but intentional — it tags every answer with the request it was for so a stale
answer for an older `attempt` is ignored, without needing an `AbortController`. Combined with
per-effect `cancelled` flags it covers the race-condition guidance in `resources/react.md`.

Routing: `/pages/:id/versions` is declared after `/pages/:id` in `Shell.tsx` but React Router's
matcher scores by specificity, so the more specific route wins — not order-dependent.

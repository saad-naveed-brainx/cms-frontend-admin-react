## Summary

Adds the invite acceptance page (users-roles T7): a public `/invite#<secret>` route that is
rendered by `App.tsx` before the session resolves. New files: `src/Invite.tsx` (the page),
`src/invites-api.ts` (lookup/accept wrappers around the open `/invitations/lookup` and
`/invitations/accept` routes), new mock stand-in `fakeInvites`, flow test on the real API, visual
baselines and the T5 `inviter` tenant.

Supporting changes: `session.ts` extracts `startSession(result, joined?)` so the invite page can
install a fresh session and land on the invited site (matched by site+role name, since the accept
response carries no site id); `signIn` returns `{ outcome, message? }` with a new `'paused'` case
for 429 responses from the sign-in limiter (users-roles T4); `SignIn.tsx` surfaces the API's own
sentence for the pause while keeping the email. New `.password-row` CSS supports the "Show"
button layout.

Stack detected: React (React 19 + Vite + react-router). No cross-repo API contract change on the
admin side — the API routes being consumed already exist in `api/src/invitations/`.

Re-review: the two Low findings from the prior pass have been addressed in the current diff —
`Invite.tsx` now manages focus via `useRef` (matching `SignIn.tsx`) and the 401 → `wrong-password`
mapping in `invites-api.ts` is scoped to the existing-account path (`name === undefined`).

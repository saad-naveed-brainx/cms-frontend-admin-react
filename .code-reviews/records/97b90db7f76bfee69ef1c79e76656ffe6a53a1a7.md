## Summary

Version-history T4 (Restore) for the admin SPA: `EditPage.tsx` learns to read
`?restore=<versionId>` from the URL, load the version together with the page,
fill the editor boxes once with the version's title/blocks/SEO (so the saved
page never flashes first and nothing typed meanwhile is overwritten), show a
notice, and strip the `restore` param from the address with a replace
navigation. The saved page remains the baseline, so Save sends only the diff
and the leave-guard trips as usual. A small CSS fix in `index.css` keeps the
`.version-row` text contrast readable on hover and when pressed (adding
`color: var(--wp-text)` and preventing the global button hover from turning
the text white; also adding `justify-content: flex-start`, `line-height: 1.5`
and `white-space: normal` so the button-styled row reads like text).

Tests are thorough: `e2e/restore.spec.ts` covers eight stand-in cases
(happy path, URL-only, saving the diff, leave-guard, idempotent restore of
"current", 404/500/offline failures, unknown-block handling, notice
replacement). `e2e/versions.spec.ts` gains a WCAG-2 contrast assertion for
the version row at rest/hover/pressed. `e2e/visual/versions.spec.ts` adds a
restored-edit-screen baseline at three widths. The real-API journey lives
in `e2e/flow/versions.spec.ts` with a new `historian` tenant and a
`versions()` helper on `realApi`. CLAUDE.md is updated.

No cross-repo API contract changes: this diff is admin-only and reads from
the existing `GET /content/:id/versions/:versionId` endpoint.

## Summary

Adds support for a single invite link covering several websites of one organization (organizations T8, D-055). `secretsOf` splits the hash on `.` with dedup, empty-filter, and a 20-cap. `Invite.tsx` now looks up each secret in parallel, enforces that all parts belong to the same email and organization, and joins them sequentially so a wrong password is tried once (not once per site) and a later failure after a first success lands the user on the first joined site with a `notice` carried via navigation state and shown by `Overview.tsx`. `invites-api.ts` extends `InviteDetails` with optional `siteId` and `organization`, remaining backwards-compatible with APIs predating organizations T1. `session.ts` prefers `siteId` for landing-site selection and falls back to the old name+role match (B-45). The `fakeInvites` mock models multi-secret invites per email (account made on the first accept, used-up tracking, accumulated memberships). Tests cover the whole matrix: UC-OR-26/27/28/29/30 (mocked), UC-OR-32 (full real-API journey with Hal/Nina), UC-OR-33 (visual, 3 widths × 2 states), and UC-OR-25 (HTML-in-names escaping across all org screens).

The implementation is careful and the test coverage is strong. The one Low finding from the previous review has been resolved.

## Summary

Adds `.github/workflows/code-review-pr.yml` to the admin repo: a GitHub Actions
workflow that, on pull_request events, averages per-commit scores from
`.code-reviews/ledger.jsonl` into a single PR score and posts (or edits) a
sticky comment on the PR with a per-commit table. The workflow is identical to
the one already carrying the api repo (both files are 4138 bytes), which is
consistent with CLAUDE.md's 2026-11-03 rule that admin and web now carry the
code-review baseline before any branches are cut from them.

Stack note: admin is a React/Vite SPA, but the changed file is CI/infra (YAML
+ bash + jq), so general correctness/security criteria apply; React-specific
rules do not. The workflow is well-structured: `set -euo pipefail`, a fork guard
(`head.repo.full_name == github.repository`) that skips untrusted fork PRs,
defensive `jq -R 'fromjson? // empty'` for malformed ledger lines, a
field-name compatibility shim (`high|major`, `medium|minor`, `low|nit`), and
three-state status logic (`neutral`/`pass`/`fail`) that correctly treats any
unreviewed commit as a fail. The ledger entries already written to the admin
repo (sample inspected: three entries from 2026-11-03) use the modern field
names (`critical`/`high`/`medium`/`low`), so the fallback shim is purely
defensive and does not affect current output.

No scope creep, no secrets, no shell interpolation of untrusted content:
ledger values flow through jq (which handles escaping) into a markdown file
that `gh pr comment` reads via `--body-file`, so there is no injection surface
on same-repo PRs (and fork PRs are gated out before this runs).
